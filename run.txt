VALERIA - LOCAL RUN GUIDE (WINDOWS / POWERSHELL)
=================================================

This guide covers a first-time local setup and the everyday start/stop routine.
Run commands from the VALERIA project folder unless a step says otherwise:

    Set-Location "C:\FullStack\VALERIA"

Requirements:
- Node.js and npm
- PostgreSQL
- Mosquitto and an existing authenticated MQTT account
- PowerShell; starting Windows services may require an Administrator terminal

Current values are generated by the software simulator. No physical sensor,
ESP32, Arduino, pump, or other greenhouse equipment is controlled.


FIRST-TIME SETUP
================

1. Install project dependencies (from the project folder):

    npm ci --prefix client
    npm ci --prefix server

2. Create local environment files only if they do not already exist:

    if (-not (Test-Path "server\.env")) { Copy-Item "server\.env.example" "server\.env" }
    if (-not (Test-Path "client\.env")) { Copy-Item "client\.env.example" "client\.env" }

   Edit server\.env with a PostgreSQL connection string for a database that
   already exists, a unique JWT secret of at least 32 characters, and the
   username/password for the existing Mosquitto backend account. The backend
   requires MQTT credentials even when the simulator uses direct mode. Keep
   these values private. Do not overwrite an existing .env file.

   The client example defaults to the local API proxy and disables mock data.
   Usually no client environment changes are needed for local development.

3. Start PostgreSQL and Mosquitto if they are stopped. Service names vary by
   computer; these are the names observed on the current VALERIA machine:

    Get-Service -Name "postgresql-x64-18","mosquitto"
    Start-Service -Name "postgresql-x64-18"
    Start-Service -Name "mosquitto"

   Run Start-Service only for a service that is stopped. If your PostgreSQL
   service has a different name, find it with:

    Get-Service *postgres*

   Mosquitto is required for MQTT ingestion. VALERIA's backend also requires
   MQTT username/password configuration when running in direct simulator mode.
   Use the existing Mosquitto configuration and account. Never recreate or
   replace an existing password file with mosquitto_passwd -c.

4. Make sure the database named in DATABASE_URL exists. Then, from the project
   folder, generate the Prisma client and apply existing migrations:

    npm --prefix server run prisma:generate
    npm --prefix server run prisma:deploy

   These commands do not reset the database. Do not run prisma migrate reset.
   Do not run the seed command against a database containing data. For a new
   account, use the website's Register page instead.

5. Start the backend in PowerShell terminal 1:

    Set-Location "C:\FullStack\VALERIA"
    npm run server:dev

   This starts the API and, outside production, the in-process simulator.
   SENSOR_INPUT_MODE defaults to direct. Do not start a second simulator.

6. Start the website in a separate PowerShell terminal 2:

    Set-Location "C:\FullStack\VALERIA"
    npm run dev

7. Open this address in your browser:

    http://localhost:5173

   The API health check is:

    curl.exe http://127.0.0.1:5000/api/health


EVERYDAY STARTUP
================

1. Open PowerShell and go to the project folder:

    Set-Location "C:\FullStack\VALERIA"

2. Check PostgreSQL and Mosquitto services:

    Get-Service -Name "postgresql-x64-18","mosquitto"

   If either service is stopped, start that service (Administrator permission
   may be needed):

    Start-Service -Name "postgresql-x64-18"
    Start-Service -Name "mosquitto"

   If your service names differ, use Get-Service *postgres* and Get-Service
   *mosquitto* to find the names installed on your computer.

3. In terminal 1, start the backend and simulator:

    npm run server:dev

4. In terminal 2, start the frontend:

    npm run dev

5. Open or refresh:

    http://localhost:5173

No daily dependency installation, Prisma generation, migration, or seed is
needed unless project dependencies/schema have deliberately changed.


OPTIONAL CHECKS
===============

Run the server tests:

    npm run server:test

Run the client lint:

    npm --prefix client run lint

Build the backend and production frontend:

    npm run server:build
    npm run build

Check the current database migration status (read-only):

    Set-Location "C:\FullStack\VALERIA\server"
    npm exec -- prisma migrate status


SHUTDOWN
========

In each terminal running npm run dev or npm run server:dev, press Ctrl+C.
The backend handles shutdown of its simulator, MQTT client, Socket.IO server,
and Prisma connection. PostgreSQL and Mosquitto Windows services may remain
running for other applications; stop them only if you intentionally want to:

    Stop-Service -Name "mosquitto"
    Stop-Service -Name "postgresql-x64-18"


SAFETY NOTES
============

- Do not run prisma migrate reset or delete the database to start the app.
- Do not run the seed script on a database with user data unless you have
  reviewed its effects and intentionally chosen that database.
- Do not change/recreate the existing Mosquitto backend account or password
  file as part of normal startup.
- Never share or commit server\.env, client\.env, database credentials,
  JWT secrets, MQTT passwords, or Mosquitto password files.
